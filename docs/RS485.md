# USART1 / RS-485 Bring-up

Status: an active, receive-first USART1 transport and the read-only native v1
protocol slice are implemented in the bridge-disabled diagnostic image. DMA,
framing, CRC, dispatch, and response generation build and pass host tests, but
no RS-485 electrical transaction has been observed on the purchased board.

## Hardware contract

The published MKS SERVO57D RS-485 V1.1 schematic routes:

| MCU signal | Board net | Transceiver connection |
| --- | --- | --- |
| PA8 GPIO | `nDIR` / `RE1` | Tied SP485E `/RE` and `DE` controls |
| PA9 USART1 AF4 | `TX` / `TXD` | SP485E `DI` through 470 ohms |
| PA10 USART1 AF4 | `RX` / `RXD` | SP485E `RO` through 470 ohms |

The SP485E receiver enable is active-low and its driver enable is active-high.
Because the two pins are tied together on this board, PA8 low selects receive
and PA8 high selects transmit. Firmware preloads PA8 low before changing it to
an output, and every transfer-error path drives it low.

There is an important hardware caveat: the schematic shows a 10 kohm pull-up
on the shared direction net. That appears to select transmit while PA8 is still
in its reset input state. The TXD net is also pulled high, so the likely reset
behavior is an actively driven idle bus rather than arbitrary data, but only a
scope measurement can prove it. Firmware cannot eliminate the interval before
PA8 takes control; a future PCB revision would need a hardware bias change if
reset-time tri-state is required.

The N32L40x pin tables identify PA9/PA10 as USART1 TX/RX on AF4. The firmware
uses asynchronous 115200 baud, 8 data bits, no parity, and one stop bit at the
current 4 MHz peripheral clock. Its rounded divider produces approximately
114286 baud, about 0.8 percent below nominal.

## DMA ownership

The transport implements the channel allocation in the real-time architecture:

- DMA channel 4 continuously moves USART1 receive bytes into a 256-byte
  circular buffer at medium DMA priority.
- Half-transfer and transfer-complete events wake foreground work at NVIC
  priority 8; they do not parse bytes.
- USART IDLE and error events also run at priority 8. IDLE is only a transfer
  boundary hint; native v1 uses an explicit delimiter, while a future Modbus
  adapter will own its required silence and timeout policy.
- DMA channel 5 moves one foreground-validated transmit frame, up to 256 bytes,
  from a fixed staging buffer into USART1.
- DMA completion disables the TX DMA request but does not release PA8. The
  USART transmission-complete interrupt releases PA8 only after the final stop
  bit has left the shifter.

The main loop drains at most 64 received bytes per pass into the native v1
streaming parser. Foreground owns COBS decoding, length and CRC validation,
address filtering, command dispatch, response encoding, and the bounded
`rs485_write()` call. The first slice responds only to valid address-1 ping,
identity, and capability requests. It never transmits at boot or in response
to noise, malformed frames, broadcasts, foreign addresses, responses, or
events. See [command protocol](PROTOCOL.md).

If foreground falls a complete buffer behind, the cursor discards the oldest
overwritten bytes and reports both an overrun event and the exact dropped-byte
count. A DMA transfer error stops the transport without an ISR retry, disables
both DMA requests, and restores receive direction. Recovery requires explicit
reinitialization.

## Diagnostic evidence

Diagnostic schema 4 preserves the schema-3 transport prefix and publishes
transport status, total received bytes, USART
IDLE/error counts, ring overruns and dropped bytes, the last drained byte, and
TX byte/frame/error/busy state. It appends native-parser readiness, accepted
frames, responses, framing/CRC/version errors, filtered traffic, and TX
rejections. The RAM record remains a separate observability channel; firmware
does not serialize its C layout or transmit unsolicited status.

## First-board procedure

Keep the motor disconnected and monitor PA6, PA7, PB0, PB1, and PB7 while
testing the communications pins:

1. At power-on and reset, scope PA8, TXD, A, and B. Record the duration and bus
   state before PA8 is driven low.
2. Confirm PA9 and PA10 idle levels and verify the UART bit time is close to
   8.68 microseconds.
3. Send known byte patterns from an isolated USB-to-RS-485 adapter. Confirm
   `rs485_rx_bytes`, `rs485_last_rx_byte`, IDLE count, and error counters.
4. Send native v1 ping, identity, and capability requests from the host.
   Confirm only CRC-valid address-1 requests receive sequence-matched replies,
   and compare the appended protocol counters with the traffic sent. Initial
   golden request vectors are recorded in [command protocol](PROTOCOL.md).
5. Confirm PA8 rises before each reply start bit and falls only after the final
   stop bit.
6. Repeat transport tests with 1, 255, and 256-byte raw TX frames, then attempt
   a second write while busy and confirm it is rejected without corrupting the
   active frame.
7. Inject COBS, length, CRC, parity, framing, and line noise errors where
   practical and confirm they are counted without an interrupt storm or
   bridge-pin change.
8. Leave the adapter silent long enough to confirm there is no unsolicited
   firmware transmission.

Passing these tests proves only the transport, direction behavior, and
read-only native protocol slice. It does not authorize any bridge output.
